# Interface design requirements

The user explicitly requested a clean, professional, coherent interface across the entire game, replacing unclear or generated-looking icons and avoiding misleading actions. They also said the current in-game arrangement is already good: preserve its useful battlefield space and familiar control positions while refining clarity. Menus and dialogs may be redesigned more substantially. This requirement remains part of the full game goal, not a claim that the current UI has met it.

Use professionally maintained, attributed SVG artwork with consistent sizing. The selected local sources are Lucide for interface controls and Game-icons.net's artist-drawn siege symbols where a generic utility icon would misrepresent the unit. Never substitute emoji, chess font glyphs, decorative sparkles or unrelated symbols for game actions. Keep readable labels, accessible names and clear selected/disabled states; icons supplement meaning.

Cover the home menu, all mode/mission setup, campaigns, custom allies/opponents/spectator setup, multiplayer lobby and join flow, settings, controls, field guide, technology tree, objectives, resources, selection and orders, minimap/camera, construction and wall tools, production/queues, alliance gifts, chat, pause/save/recovery/update, and victory/defeat. Costs must name resources, player/team relationships must be explicit, and saving/hosting/pause descriptions must match actual behavior.

Responsive checks include small landscape phones (568 by 320, 640 by 360, 667 by 375), wider phones (844 by 390), portrait phones (320 by 568 and 360 by 640), tablets (768 by 1024 and 1024 by 768), desktops (1280 by 720, 1366 by 768 and 1920 by 1080), and wide/large screens. Respect safe areas, scrolling and keyboard focus. Keep primary touch targets at least 44 by 44 CSS pixels, mobile text inputs at 16px or more, and secondary battlefield controls collapsible. Screenshots must be reviewed in addition to overflow and bounds checks.

UI work can affect frame time. Avoid backdrop blur over the continuously rendered battlefield, heavy animated effects, unnecessary DOM replacement, layout reads in the render loop and large new runtime dependencies. Shared cached vector assets and event-driven updates are preferred. Measure the revised UI against the unchanged production baseline on the same scene and browser; inspect layout/paint activity and repeated DOM updates as well as frame timing. Do not promise zero lag on every device based on emulation or a paused screenshot.

Verify real actions after visual changes: selection and deselection, camera input, touch button activation exactly once, paid training, wall preview/confirmation/cancellation, settings apply, dialog close/focus restoration, human/AI setup, room readiness, chat, gifts and end states. Existing multiplayer, fog privacy, simulation and renderer checks remain required. Physical-device and human usability evidence remain necessary for the broader release goal.
