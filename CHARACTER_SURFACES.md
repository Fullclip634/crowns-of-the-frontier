# Blender character surfaces

The shared troop palette now uses original Blender-authored cloth, leather, forged-metal and skin textures. Previously, importing the catalogue replaced Blender materials with flat shared colors; changes made only in Blender's material editor did not reach the live troop shader. Per-vertex surface codes now retain those material roles after joint merging, and both WebGPU's node graph and WebGL's GLSL palette sample the same atlas.

Team colors remain independent of texture shading. Cloth applies to humanoid team garments, canvas and trousers; ship team paint and painted shields keep their original surfaces. Leather, steel/iron and skin retain their own roles. Timber still uses the existing wood surface. Geometry, animation pivots, tool grips, troop statistics and the rest of the model catalogue are unchanged in this material pass. Face, garment and boot silhouettes still need further authored refinement; this is not completion of the full character-art goal.

The two padded 512 by 512 atlases total 739,666 bytes on disk. The color image uses sRGB. The second image stores tangent-space OpenGL normals in RGB and roughness in alpha, with no color conversion or alpha premultiplication. Blender's bottom-origin tile ordering is preserved by loading these images with `flipY=true`. Each tile has a 224-pixel core and 16-pixel wrapped padding. Cloth, leather, metal and skin use different repeat rates to avoid oversized weave and pores.

Performance uses the color atlas with the existing roughness values. Balanced adds normal/roughness detail at reduced strength; High uses full detail strength. Fine shading fades between camera distances 18 and 44 to reduce distant shimmer. The node and compatibility shaders skip fine texture sampling when that contribution is absent. Downgrading clears the palette's normal reference, allowing the residency cache to release it once scene and portrait references no longer need it. Atlases are shared between troop types and instances rather than copied per character. A full RGBA mip chain is approximately 1.33 MiB per atlas before backend overhead.

Run `npm run art:characters` to reproduce the material library and candidate bakes in `.tools/art-candidate/character-surfaces`. The editable `character-materials.blend` includes the procedural materials and 3D surface studies. `npm run art:characters -- --promote` validates dimensions, hashes and file budgets before copying the atlas files and manifest into `src/assets3d/characters`. The authoring script uses the installed Blender 4.5 LTS executable, or `BLENDER_BIN`. It does not regenerate unrelated world models.

`tests/character-surfaces.test.js` decodes the actual PNG bytes, verifies packed normal lengths and roughness against the Blender manifest, checks tile ordering, hashes, file budgets and material/profile assignments. The actual worker catalogue's batching regression checks that all four surface codes survive merging alongside solid bounds and articulated motion.

Production browser checks passed on WebGPU and WebGL through High to Balanced to Performance and back, including material bindings/residency and painted frames. Separate pixel comparisons confirmed that both albedo and normal/roughness shading affect the rendered troops. Normal RTS camera views and emulated phone coverage at 568 by 320 with Performance graphics also passed without page errors or horizontal overflow. Crowded-army checks rendered 144 figures across six unit types in six troop batches with shared atlas references. These controlled rendering checks do not establish sustained frame rate, thermals or compatibility on physical phones. Full hardware and art acceptance remains in [QUALITY_TARGETS.md](QUALITY_TARGETS.md).

Implementation references: Blender's [Principled BSDF material model](https://docs.blender.org/manual/en/4.5/render/shader_nodes/shader/principled.html), Three.js's [standard material](https://threejs.org/docs/pages/MeshStandardMaterial.html) and [TSL API](https://threejs.org/docs/pages/TSL.html). The installed Three.js implementation determines the supported shader behavior.
