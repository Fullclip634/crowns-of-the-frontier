# WebGPU shadows and calm green terrain

An Android-path browser test reproduced a game rendering defect on a real WebGPU device with Compatibility Mode validation and no optional GPU features. Compared shadow depth was declared as a depth texture while the manual comparison path performed a vector-channel load. That generated invalid WGSL. A scalar-only correction also exposed Compatibility Mode's prohibition on fragment-stage depth-texture loads; the [captured failure](artifacts/webgpu-depth-sampling-before.json) records that restriction. These tests identify a real game defect, without proving it was the sole cause of either reported physical-device failure.

Compatibility renderers now use a non-comparison depth binding and a five-sample manual PCF filter with the same Vogel disk distribution used by the existing filter. Shadow map sizes, bias, normal bias and actual shadow casting remain in place. Both regular and reversed depth comparisons are supported by the filter. Core WebGPU and classic WebGL keep their existing shadow implementation. The fix does not modify dependency files or globally patch the Three.js engine.

The strict browser test creates an actual device with no optional features, confirms Compatibility Mode is active, runs the Android code path, and exercises High, Balanced and Performance settings. Construction clipping, solid troop poses, placement previews, weather, night lighting, portraits and visible phone repaint are checked as well. This is host-GPU validation with an isolated blocklist override, not a test of every Android GPU driver or a physical Infinix phone.

Non-winter maps use muted green ground colors and grass shading, with less background soil coverage. Roads and banks retain their own material; rocky slopes retain their elevation-driven rock coverage. The legacy `desert` map identifier remains valid for saves and rooms, while its displayed name and appearance become **Sunlit meadows**. Minimap and custom-battle preview colors use the same biome styles. Grass uses the existing solid instanced meshes and capacity limits. More of the old steppe/frontier's existing capacity can be visible because their dry, sparse-grass rule was removed; this is not a claim of unchanged frame time. Winter's main ground palette and grass tint are preserved.

Settings and graphics recovery include a collapsed **Graphics support report**. It keeps the original failure, build, quality, browser and selected GPU limits across compatible reloads in the current tab. The report excludes game state and room identifiers, bounds driver text, and removes addresses and credentials from that text. Nothing is uploaded automatically. **Copy report** supports normal clipboard access and explicit manual selection when clipboard access is denied. The ordinary game's text-selection prevention remains active outside that report.

Use `?renderer=webgpu` to explicitly retry native rendering after an update, including in a tab that previously remembered compatible graphics. A failed startup can still recover into WebGL; active games retain their existing save/reload protection. The broader RTS goal remains active, including visual refinement, balance and physical-device validation.

References: [WebGPU Compatibility Mode proposal](https://github.com/gpuweb/gpuweb/blob/main/proposals/compatibility-mode.md), [Chrome's Compatibility Mode support](https://developer.chrome.com/blog/new-in-webgpu-146), and the pinned Three.js 0.186.1 source inspected locally. Compatibility depends on actual browser, OS and driver support; this release does not establish universal WebGPU availability.

Verification records are collected in [the milestone report](artifacts/device-support-validation.json): 439 regression tests, a production build, [normal WebGPU](artifacts/device-support-default-phone/validation.json), [strict Compatibility Mode](artifacts/device-support-compatibility-phone/validation.json), [classic WebGL](artifacts/device-support-webgl-phone/validation.json), and [recovery and support-report checks](artifacts/device-support-recovery-chrome-d3d11/validation.json). Each normal renderer covers seven maps across all three presets. The WebGL map run reached its browser deadline after all 21 map cases; phone repaint and preset checks are completed in a separate run against the same build, with both original records retained. Phone viewport checks cover 568×320 and 740×360, including visible battlefield pixels and no horizontal overflow. Clipboard denial, fully unavailable graphics, tab-retained original errors, and saving and resuming a held match are exercised as well.

All seven Balanced map captures were reviewed visually, including [Highlands](artifacts/device-support-default-phone/terrain-highlands-medium.png), [Sunlit meadows](artifacts/device-support-default-phone/terrain-desert-medium.png), [Coast](artifacts/device-support-default-phone/terrain-coast-medium.png) and [Winter](artifacts/device-support-default-phone/terrain-winter-medium.png). These are functional and visual checks on the test host, not measured physical-phone performance or confirmation of the user's device-specific problem.
